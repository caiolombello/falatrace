# FalaTrace 0.2.0-alpha.14

Experimental Linux source release: everything is configurable from the Studio, with a guided first use, write-only API keys, verified model downloads on request, an English interface and an install path from source. Alpha.13 settings, alpha.12 call-app identities and alpha.11 consent, revision and export contracts are unchanged.

## Changes

**First use.** On a computer without a configuration the Studio opens a six-step assistant: language and consent, capture with a five-second audio test, processing presets (everything local, local transcription with an OpenAI summary, or everything through OpenAI) with model downloads and the OpenAI key when needed, automatic recording, review, and the services to start. Nothing is saved or installed before Finish, the OpenAI key included; the audio test and model downloads run only from their own buttons. The first save writes every explicit choice, so a later default change cannot alter it. Review diagnoses the choices it lists, and the last page names anything still missing, such as a model to download. See the [quickstart](QUICKSTART.md) ([português](QUICKSTART.pt-BR.md)).

**Settings for every option.** The settings dialog has ten sections and covers every field in the allowlist. The [configuration reference](CONFIGURATION.md) lists them with values and defaults.

| Section | New in alpha.14 |
| --- | --- |
| Captura e áudio | Five-second audio test with a level per track; frame rate. |
| Processamento e IA | Presets, Whisper.cpp threads, expected languages, transcription vocabulary, Ollama input limit, completion notifications. |
| Chaves de API | Save, test and remove `OPENAI_API_KEY`, `GEMINI_API_KEY` and the OBS WebSocket password. |
| Modelos | Whisper and Ollama models with explicit consent per download. |
| Integrações | OBS, remote worker with an SSH test, originals archive, Proton Drive and legacy S3. |
| Recursos opcionais | Timesheet, per-client AI context, GNOME Calendar title. |
| Avançado | Studio language, detection sampling and test mode, capture timeout, folder naming, legacy GNOME options, visual review limits, retention, background check interval. |
| Serviços e diagnóstico | Processing, archive and Proton backup timers next to the call monitor and tray; each problem links to the section that fixes it. |
| Backups e transferência | Restore a backup, export without keys (never over the configuration in use), import into the draft. |

**API keys.** Keys are written to a private `secrets.env` (0600) next to the configuration, which background jobs read. The Studio and `falatrace keys` save, test and remove them and never show a value. **Test** asks the provider only for its model list. Explicit precedence: session environment, `secrets.env`, `worker.env`, `calls.env`, then a legacy `openai.apiKey`. Diagnostics explain keys that exist only in the Studio's session, key files readable by other users and older sources that shadow the Studio key. A legacy key file that is rejected (writable by others, owned by someone else, a link or too large) is never used, even when a service loads it into its environment.

**Models.** Official whisper.cpp models are downloaded in a transient user unit and accepted only when size and SHA-256 match the pinned values; a different file with the same name is kept. A model counts as installed only after that check, and **Download** on a file that is already there only checks it. Ollama pulls go only to an Ollama on loopback. Running downloads and pulls can be cancelled. CLI: `falatrace models list|download|ollama-pull`.

**Services and timers.** Apply, restart or disable the call monitor, tray and the `recording-cli-sync`, `recording-cli-archive` and `recording-cli-proton-backup` timers, with next and last run and a warning when a unit still uses an older configuration. A desktop notification reports a finished or failed job (`processing.notifyOnCompletion`). New `uninstall-timer` commands for jobs, archive and backup.

**Process any recording.** **Process…** in a recording's header shows what will happen (create, queue or retry), the duration, where transcription and summary run and, for remote processing, the worker's address, and marks destinations that leave the computer. The job is queued only after consent bound to that exact plan; a changed file, configuration or worker asks again.

**Assistant connection.** For an active agent grant, **AI access → Connect my assistant…** shows the command that registers FalaTrace's local MCP server with Claude Code, Codex CLI or Gemini CLI, under a server name of its own for each grant. The Studio installs and runs nothing.

**English.** The Studio follows the system language (Portuguese for `pt_*` and bare `C`/`POSIX` locales, English otherwise) or `studio.language`. Bridge messages are translated too; user content (meeting titles, transcripts, speaker names) never is.

**Install from source.** `make install-studio` builds the Studio with the local Qt headers (system packages or `bun run desktop:setup`), installs it under `~/.local/share/falatrace/studio` and adds the `recording-studio` launcher, a `falatrace-studio` alias, a menu entry and the icon, without sudo or downloads. `make uninstall-studio` removes only what it created.

**Fixes.**

- Keys found in `calls.env` were reported as working but never reached background job units.
- The placeholder worker host counted as configured.
- Diagnostics showed the manual backend instead of the one automatic recording uses, and the monitor could be applied with a backend that cannot record.
- Captures started by legacy backends can be stopped from the Studio.
- Compiled binaries generate working GNOME helper and service commands.
- Units written from source runs launch the CLI instead of the bridge script.
- An unknown `backend` value is refused when the configuration loads. Five never-read `features` defaults were removed; old files still load.

## Verification

931 offline tests, 0 failures across 129 files. TypeScript, desktop type checks, Biome lint on the new modules and the CLI build passed, locally and in public CI.

The real QML ran offscreen in eight journeys with 323 assertions. They use `scripts/studio-qml-runner.py`, a PySide6 port of `main.cpp` with the same arguments, JSONL validation, timeouts and snapshot receipts, against synthetic bridges. CI runs them in a new `studio-journeys` job with PySide6 6.11.2 pinned by hash. New journeys cover every settings section and the assistant, **Process…**, the assistant connection commands and the English interface. A side-effect guard fails a journey on any save, service action, key, download or restore it did not intend, and saved keys never appear in output.

New unit coverage includes the secrets file and key precedence, the key test, model downloads and pulls, the manual processing plan, the audio test, timers, the installer end to end (including running the generated launcher), the translation dictionary (every `t()` literal has an English entry; placeholders and joining spaces are kept; real diagnostic, capture, queue, model and key-test messages come out in English) and the documentation (every editable field documented, the example configuration valid).

The alpha.13 known issue in `scripts/test-local-ux.py` is fixed for its synthetic frames modes, which now wait for the preview and result instead of fixed delays. Its real-flow modes and the scope and planner journeys still use fixed delays (see Limits).

## Limits

- The shipped `recording-studio` binary and MpvQt playback were not exercised; the journeys use the PySide6 port.
- The real-flow modes of `test-local-ux.py` and the scope and planner journeys still drive the frames flow with fixed delays. In a slower container they failed in some runs, on this release and on the previous head alike, and passed in others; they passed in CI.
- The system-Qt build path was not compiled here: the build environment had Ubuntu 24.04 with Qt 6.4 and no `libmpvqt-dev`. The tested native runtime remains Qt 6.10 with MpvQt.
- Real capture, real providers, real model downloads, native file dialogs, physical keyboard and screen readers were not exercised.
- The CLI, TUI and tray stay in Portuguese. A bridge message without an English entry is shown in Portuguese.
- Whether new users can explain where their data goes has not been checked with people.
- All alpha.13 limits not listed as fixed remain.

## Installation and rollback

Alpha.13 remains available for rollback. Update only when no capture or processing is active. Existing configurations load unchanged unless they name an unknown `backend`, which now has to be corrected. Keys in the environment, `worker.env` or `calls.env` keep working and can be moved to `secrets.env` under **API keys**. After updating, apply the call monitor and timers again if the diagnostics flag them. Existing MCP sessions may need reconnecting to use the new executable. This document describes the release, not an installed-state receipt.
